# AGENTS.md

## Cursor Cloud specific instructions

This repo is **`deepseek-rs`**, an unofficial **macOS-only** Tauri v2 desktop wrapper around the
published `@deepseek-ai/dsh@0.1.0-rc.7` web profile. Standard setup/commands live in
[`README.md`](README.md), [`CONTRIBUTING.md`](CONTRIBUTING.md), `package.json` scripts, and
[`.github/workflows/ci.yml`](.github/workflows/ci.yml) — read those first and don't duplicate them here.

The Cloud Agent VM is **Linux/x86_64**, so only the parts of CI that run on `ubuntu-24.04` can run
here. The notes below are the non-obvious caveats.

### Node version (important)
- The `node` first on `PATH` (`/exec-daemon/node`) is **v22.14.0**, which is **below** the project's
  `engines` floor (`^22.19.0 || >=24`). `pnpm` itself runs on a compliant Node under nvm, but scripts
  it spawns inherit the `PATH` `node`.
- A compliant Node **v22.22.2 is preinstalled via nvm**. Put it first on `PATH` before running any
  build/test/`dsh` command:
  `export PATH="$(dirname "$(nvm which 22)"):$PATH"` (or `nvm use 22`). The update script installs
  dependencies but does not change your shell `PATH`.

### What runs on this Linux VM (all after `pnpm install`)
- `pnpm build` — frontend web build (`tsc && vite build`).
- `pnpm run check` — typecheck + `scripts/prepare-bundle.mjs` bundle unit tests.
- `pnpm --dir plugins/dsh-llm-grok test` — 120 `node --test` cases for the Grok plugin.
- `pnpm audit --prod` — production dependency audit.
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check` — Rust formatting only.

### What CANNOT run on Linux (macOS-only by design — do not fight it)
- `cargo build` / `cargo test` / `cargo clippy` for `src-tauri`: the crate has
  `#[cfg(not(target_os = "macos"))] compile_error!("deepseek-rs targets macOS only")` in
  `src-tauri/src/lib.rs`, and Tauri's Linux deps (`gdk-3.0`/GTK/WebKit) aren't installed. CI runs
  these Rust checks on `macos-14` only. Don't install GTK/WebKit here — the crate can never link on
  Linux regardless.
- `pnpm tauri dev` / `pnpm tauri build`: the native window (WKWebView) requires macOS 14+ arm64.

### Exercising the product end-to-end on Linux
The app's whole job is spawning `dsh --profile web` and opening its loopback GUI in a WKWebView. You
can run that same host directly to verify the core functionality:

```sh
node node_modules/@deepseek-ai/dsh/lib/bin.js --profile web --host 127.0.0.1 --port 0
```

It prints a readiness line `dsh web: http://127.0.0.1:<port>` (this exact format is what
`src-tauri/src/host.rs` parses). Opening that URL serves the full DeepSeek Harness web GUI. A real
model conversation additionally needs `DEEPSEEK_API_KEY` (set in the environment or `~/.dsh`); the GUI
renders and is usable without it (it shows an "add API key" onboarding modal you can dismiss).

### Other notes
- `vendor/runtime/` is generated by `scripts/prepare-bundle.mjs` during `pnpm tauri build` (downloads
  ~400MB of Node + `dsh`). It is macOS-packaging-only and gitignored — never commit it.
- Keep `@deepseek-ai/dsh` pinned exactly at `0.1.0-rc.7` (see `CONTRIBUTING.md` change rules).
